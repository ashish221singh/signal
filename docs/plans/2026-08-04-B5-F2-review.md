# B5–F2 (Config + Sheet + SDKs) — Cross-Review & Gap Reconciliation

> Reviews the remaining planned work as a set — B5 (post-submit actions), F1 (web-core
> sheet), F2 (SDKs/shells) — for coherence, sequencing, and integration holes.
> The reporting dashboard and landing page are intentionally **not planned yet**.

## Verdict
Coherent and correctly ordered (config → renderer → transport). The load-bearing idea —
**web-core is pure/never networks; shells own all I/O** — holds across every surface and makes
the sheet testable and identical everywhere. Each plan now carries an explicit
"Edge cases & failure modes" section. Five cross-cutting gaps below; none force a re-plan.

---

## Gaps & resolutions

**GR-1 — A stable API URL / host is needed to *ship* F2 (not to build).** The SDK bakes in an
`apiUrl`; the hosted link must be served; `connect-src` CSP guidance needs the real API origin.
Resolution: **local dev is fully unblocked**. Before F2 ships, settle the API host/domain
(Railway/Fly rec) and the hosted-link path. Dashboard/landing domains are out of scope until
those plans exist.

**GR-2 — Native SDKs can't import the TS contracts.** web-core owns the config types
(`@signal/contracts`, TS); Kotlin/Swift can't consume them. Resolution: **native shells never parse
the full config** — they relay the eligibility JSON straight into the bundled web-core and only
implement the small, stable **bridge message schema** (`ready/submit/dismiss/resize/requestUpload/
openUrl/openReview`) + the eligibility request/response envelope. Author `docs/sheet-bridge-v1.md`
in F1; F2's native shells consume it. This is the single cross-language contract.

**GR-3 — Image-upload ownership across surfaces.** F1 routes it through `host.requestUpload`.
Resolution: **default to web-core-context `fetch`** (presign → PUT, one code path for web + native
WebView); a shell overrides only if it needs native upload control. Images upload immediately (not
via the response outbox); only the resulting URL rides the precious response. On failure, the
answer still submits text-only (never blocked on an image).

**GR-4 — Hosted-link preview is a small backend addition inside F2.** F2-D7's preview token +
standalone harness is an API endpoint. Resolution: acceptable — account-scoped, short-lived token,
serving a frontend surface; build it in F2 Task 3, document in `docs/api-v1.md`, and give the
standalone page a default `SheetHost` (preview mode may be read-only / non-persisting).

**GR-5 — `tokens.css` must stay one source of truth.** web-core inlines it; the hosted link uses
it; later the dashboard/landing will. Resolution: **publish tokens once** — a tiny `@signal/tokens`
workspace package (or a single referenced `design/final-version/tokens.css`) imported wherever
needed. No copies. Decide the mechanism in F1.

## Consistency checks across the three plans (all resolved)
- **`trigger_id` idempotency** ties the loop together: F1 reports submit/dismiss → F2 outbox flushes with retry → backend dedups. No double-count on replay. ✔
- **Suppression** is decided server-side but short-circuited client-side (F2-D11); dismiss vs submit semantics live in the backend, the sheet only reports the event. ✔
- **Anonymous id** (F2-D9) gives suppression a stable subject when the host has no `userId`. ✔
- **Post-submit `store_review`** intent (B5) degrades gracefully where unsupported (F1/host), e.g. web/hosted-link. ✔
- **Negative branch with no capture** (F1-D12) is consistent with B5 (rating-only workflows are valid). ✔
- **Custom SVG emoji** (F1-D11) ⇒ identical rating UI on every shell; native never renders system emoji. ✔

## Accepted-by-design / notes
- **iOS + RN are a fast-follow** (F2-D1): ship **web + Android + hosted link** first; iOS/RN trail without blocking.
- **Chips/Reasons stay dropped** for v1; negative signal is comments + photos. `chips_on_negative` stays in the schema unused (B5-D6).
- **PII/consent:** the sheet collects free-text + photos (end-user PII); integrator is controller, Signal processor. Erasure covered by B4's user-data delete; a short privacy note belongs in docs. Full DPA/consent tooling deferred.
- **Reporting dashboard + landing page:** deliberately **not planned yet** — the data they'd show already flows to the backend.

## Net changes folded into the plans
- **Sequencing:** B5 → F1 → F2. (Dashboard/landing later.)
- **`docs/sheet-bridge-v1.md`** — cross-language bridge schema (GR-2), authored in F1, consumed by F2.
- **Tokens single-source** (GR-5) — decided in F1, reused by shells/hosted link.
- **API host/domain** (GR-1) — settle before F2 ships; local dev unblocked meanwhile.

## Current roadmap
Backend **B1–B4 ✅ merged** → **B5** config extension → **F1** web-core sheet → **F2** SDKs/shells
(web + Android + hosted link first; iOS/RN fast-follow). Reporting dashboard + landing page: later.
